Codex Provider Session Sync 系统运行流程

这个程序的核心目标是把 Codex Desktop 在不同 model_provider 下产生的会话聚合成同一批可见历史。它不是聊天客户端，而是一个后台同步器：读取本地会话文件，生成或刷新跨 provider 的镜像副本，并维护索引与备份。

Tauri + React + Rust

一眼看懂

1

程序启动

启动 Tauri 桌面壳，创建主窗口、托盘图标和后台线程。

2

读取配置

读取 .codex/provider-session-sync.json，得到开关、间隔和 provider 列表。

3

扫描会话

扫描 sessions 与 archived_sessions 下的 JSONL 文件。

4

同步镜像

按会话 lineage 生成或刷新其它 provider 的镜像会话文件。

5

展示状态

主界面展示会话组、同步副本、Provider 分布、日志和备份。

模块职责

前端 UI

src-ui/main.tsx 负责窗口界面、按钮点击、状态刷新、日志和备份列表展示。

Tauri 后端

src-tauri/src/lib.rs 负责托盘、自启动、后台线程、命令入口和操作互斥锁。

同步核心

src-tauri/src/sync.rs 负责扫描 JSONL、识别 provider、生成镜像、更新索引。

配置管理

settings.rs 管理同步开关、间隔、provider 列表和默认路径。

备份恢复

backup.rs 创建快照、列出快照、恢复指定快照。

系统集成

Windows 托盘图标、HKCU Run 开机自启、release exe 都由 Tauri 侧处理。

启动流程

普通启动
运行 exe→ Tauri 初始化→ 创建主窗口→ 创建托盘图标→ 启动后台同步线程

关闭窗口不会退出程序，只会隐藏窗口；托盘仍然保留，后台线程继续按间隔同步。

开机自启
点击开启自启→ 写入 HKCU Run→ 下次登录 Windows 自动运行 exe

开机自启只写当前用户注册表，不需要管理员权限。

托盘交互
左键点击托盘→ 显示主窗口 右键菜单→ 打开面板 / 开关同步 / 设置间隔 / 退出

同步流程

输入数据

C:\Users\<用户名>\.codex\sessions

C:\Users\<用户名>\.codex\archived_sessions

C:\Users\<用户名>\.codex\session_index.jsonl

输出数据

其它 provider 的镜像 JSONL 文件。

更新后的 session_index.jsonl。

同步日志和同步前备份快照。

1

创建同步前备份

每次同步前先创建 before-sync 快照，降低写坏数据的风险。

2

读取 session_meta

每个 JSONL 中找到 type=session_meta 的记录，提取 ID、provider、fork 来源。

3

按 lineage 分组

真实会话用自己的 ID；镜像会话用 forked_from_id 回到原始会话组。

4

选择 canonical

在真实源会话中选出最适合的主来源，用它渲染其它 provider 的副本。

5

写入镜像和索引

改写镜像的会话 ID、provider、fork 来源，并补充索引行。

关键数据字段

字段 来源 作用
session_meta.payload.id JSONL 会话文件 会话 ID。镜像文件必须使用不同 ID，否则 Codex 会把它们当成同一个会话。
model_provider JSONL 会话文件 决定会话属于 openai、openrouter、custom 等哪个 provider。
forked_from_id 镜像会话文件 标记这个会话是从哪个真实会话镜像来的，用于跨 provider 聚合。
session_index.jsonl Codex 索引文件 让 Codex Desktop 的会话列表能看到新增或刷新后的镜像会话。

首页指标口径

会话组

跨 provider 聚合后的对话数量。一个真实会话加上它的多个镜像副本，只算一个会话组。

同步副本

当前工具维护的镜像/fork 副本数量，也就是带 forked_from_id 的同步副本。

上次同步

后台同步或手动同步最近一次完成的本地时间，格式为 YYYY-MM-DD HH:mm:ss。

备份与恢复

备份什么时候发生

  • 自动同步发现会话或索引需要写入时，才创建 before-sync 快照。
  • 手动点击备份时创建 manual 快照。
  • 执行恢复前先创建 before-restore 回退快照。
  • 默认保留最近 24 个自动备份、10 个手动备份、10 个恢复前备份。

恢复时要注意

  • 恢复会覆盖 .codex 下的会话目录和索引。
  • 建议恢复前关闭 Codex Desktop，避免它同时写会话文件。
  • 恢复操作和同步操作共享互斥锁，避免一边恢复一边同步。

为什么不能用软链接

这个工具不是简单复制文件名。镜像会话必须改写 session_meta.id、model_provider 和关联的 thread/session ID，才能让不同 provider 看到“同一内容但不同身份”的会话。因此软链接会导致多个 provider 指向同一个原始 ID，无法正确出现在各自 provider 的会话列表里。

异常与安全策略

冲突跳过

如果目标文件已存在，但它的 ID 或 provider 不符合本工具生成规则，程序会认为它不是自己的镜像文件，跳过写入并记录冲突数。

全局写入锁

同步、手动备份、恢复、保存开关和间隔共享同一个操作锁，避免多个写操作同时改 .codex。

日志尾部读取

日志界面只读取日志文件尾部，再展示最后 80 行，避免日志变大后 UI 卡顿。

窗口关闭逻辑

关闭主窗口只隐藏窗口；真正退出需要点击 UI 或托盘菜单里的退出。
